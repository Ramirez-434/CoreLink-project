1. Pendência Selecionada e Priorização

Prioridade: Alta

Funcionalidade Escolhida: Prevenção de Requisições Duplicadas — Adição de controle de estado (isLoading) nos botões de checkout e no formulário de status do Painel Admin, eliminando o envio repetido por duplo clique.

Justificativa Técnica: Em fluxos críticos de e-commerce B2B, o acionamento repetido (double-click) de botões de submissão pode disparar requisições concorrentes antes que o ciclo assíncrono de renderização do React aplique o atributo disabled no DOM. Sem bloqueio imediato e idempotência no servidor, um duplo clique no checkout ou no Painel Admin geraria cobranças/pedidos duplicados no PostgreSQL, consumo dobrado de cupons, baixa múltipla de estoque e reenvio de e-mails transacionais.

2. Resultado Esperado e Comportamento Alcançado

0% de Duplicidade

Foi implementada uma defesa em 3 camadas complementares: (1) Trava Síncrona Imediata (useRef) nos componentes CheckoutForm.tsx, carrinho/page.tsx e OrderStatusControl.tsx que intercepta cliques em menos de 1ms no mesmo tick do JavaScript; (2) Controle de Estado Reativo (isLoading) que desabilita botões e campos (disabled, aria-busy, pointer-events-none) exibindo spinner animado (Loader2); e (3) Guarda de Idempotência Server-Side (order.ts) com janela de 15s em createOrder e verificação de igualdade de estado em updateOrderStatus.

// src/actions/order.ts — Janela de Idempotência (15s)
const duplicateWindow = new Date(Date.now() - 15_000);
const existingRecentOrder = await prisma.order.findFirst({
  where: {
    userId: session.user.id, productId: product.id,
    status: "PENDING", createdAt: { gte: duplicateWindow },
  },
});
if (existingRecentOrder) {
  return { success: true, orderId: existingRecentOrder.id, deduplicated: true };
}

7. Roteiro de Validação e Testes de Homologação

Cenário de Teste Procedimento Executado Resultado Obtido na Homologação
Duplo Clique no Botão "Confirmar Pedido" Acionar rapidamente 3 cliques consecutivos no botão de submissão do CheckoutForm.tsx. O 1º clique ativou checkoutLockRef e isLoading=true (spinner "Processando Pedido..."); os cliques #2 e #3 foram descartados com 1 único pedido gravado.
Duplo Clique no Formulário de Status Admin Selecionar "Completed" em /admin/pedidos e clicar repetidamente no botão "Salvar". O <select> e o botão entraram em estado disabled ("Salvando..." + selo de bloqueio), executando apenas 1 transação no Prisma ORM.
Tentativa de Salvar Status Sem Alteração Manter o mesmo status já persistido no banco e verificar disponibilidade do botão "Salvar". Como hasChanged === false (status === persistedStatus), o botão permanece desabilitado, evitando queries UPDATE desnecessárias.
Idempotência Server-Side (order.ts) Disparar duas chamadas concorrentes para createOrder e updateOrderStatus na mesma janela de 15s. A Server Action identificou o registro recém-criado/atualizado e retornou deduplicated: true sem duplicar pedido, estoque ou e-mail.
